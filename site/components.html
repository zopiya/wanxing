命名与状态约定

wx- 前缀，BEM-lite，只允许一层 __。 完整 BEM 会产出 wx-article__header__title--large，正是这套系统在别处禁止的"产品味"。

.wx-note          块 Block
.wx-note__title   元素 Element —— 只有一层
.wx-note--warn    修饰 Modifier

.wx-toc__link[aria-current]   状态 —— ARIA，不是 class
.wx-btn[disabled]             状态 —— 原生属性
.wx-collapse[open]            状态 —— 原生属性
为什么状态不用 class

这条规则是从"禁止仅用颜色区分状态"推导出来的。把 CSS 状态绑定到无障碍树上， 在结构上不可能出现读屏器感知不到的状态——因为样式本身就依赖那个属性。 用 .is-active 时，视觉状态和无障碍状态是两个可以各自漂移的事实。

明确不做的

有两类排除，理由不同，处理方式也不同。

组件为什么不做
卡片 Card哲学——四边包围的方框不携带信息。用 wx-entry
加载动画 Spin哲学——旋转是被禁的循环动画。用文字说明
骨架屏 Skeleton哲学——静态占位就是一根线，shimmer 是禁止的循环
轮播 Carousel哲学——自动轮播移动读者正在读的内容。用 wx-gallery（手动滚动）
水印 Watermark哲学——纯装饰性叠加
颜色选择器 · 级联选择 · 提及工程成本——需要大量 JS，且原生替代品可用

哲学性排除不会随范围扩大而放开——它们是这套系统的身份。 工程性排除只是暂时的，有需要时可以做。
