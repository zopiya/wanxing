组件 · Components

组件能力地图

组件不是一堆 CSS 类，而是让页面在“阅读、输入、定位、反馈”之间保持同一语言的公开契约。

建立结构

布局与通用

页面宽度、节奏、规则、动作、属性和品牌标记。先让信息有秩序，再加任何交互。

page · container · stack · cluster · rule · btn · tag · avatar

帮助人找到位置

导航

站点、目录、页内锚点、分页、步骤和标签页；状态统一由 ARIA 或原生属性表达。

nav · sidebar · anchor · tabs · pagination · steps

接受输入

数据录入

字段、选择、范围、上传与搜索。输入类无论在哪条轨道都按可用性惯例处理。

form · field · input · select · switch · upload · search

展示内容与关系

数据展示

条目、表格、树、图、图集、时间线和代码；用内容结构替代四边封闭的卡片。

entry · table · tree · timeline · figure · gallery · code

明确反馈

反馈与浮层

提示、进度、结果和 dialog。浮层是有限例外：有边界，但无阴影和渐变。

note · toast · progress · modal · drawer · popover

每一类页面都应回答四件事

你需要的答案文档中在哪里为什么这比样式截图重要
何时使用 / 何时不用五个类别页各自的 API 区避免把“有一个组件”误解为“任何场景都该用”。
最小 HTML / ARIA 契约运行中的 demo 与自动生成的 Source展示代码永远从真实 demo 派生，不会手工漂移。
是否需要行为脚本组件页面和行为脚本表没有 JS 时仍可阅读；需要 JS 的地方被明确标出。
是否经过底线验证无障碍与 RTL颜色、静态标签/命名、站点结构和审计器夹具可复现；设备级事项不伪装成自动覆盖。
