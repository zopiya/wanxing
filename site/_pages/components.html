组件与组合

组件是 kit 的第三层：token 给出不变数值，基础层给出跨页面底线，pattern 组织页面；组件只负责可复用的内容、交互与反馈单元。

先分清构件层级

Tokens

数值与语义

颜色、字族、间距、时长、描边等唯一真源。它们不表达业务 UI，也不在 prose 里复制数值。

Patterns

页面组织

A–E 回答一页内容怎么读、怎么找、怎么完成任务。它们是骨架，不能被 button 或 card 替代。

Components

可复用单元

表单、导航、内容展示和反馈。每一个有最小 HTML、ARIA 或原生属性契约，必要时才有行为脚本。

Behaviours

渐进增强

tabs、overlay、toc、disclosure 等只补平台缺口；移除脚本后不能让内容或基础操作消失。

组件族按职责，而非视觉外形划分

结构与语义

布局与通用

page、container、stack、cluster、rule、btn、tag、avatar。它们建立页面节奏和动作语义，不创建四边封闭的“面”。

定位与连续性

导航

nav、sidebar、anchor、tabs、pagination、steps。当前位置、选中和展开统一由 ARIA/原生属性承载。

输入与任务

数据录入

form、field、input、select、switch、upload、search。它们不服从“极简优先”，而服从第三层：表单就是表单。

内容与关系

数据展示

entry、table、tree、timeline、figure、gallery、code。分组以标题、邻近、单边线和结构语义完成。

状态与反馈

反馈与浮层

note、toast、progress、modal、drawer、popover。浮层是可用性例外：允许边界，不允许阴影和渐变。

公开构件目录

目录来自 kit/components/manifest.json，构件不能只留下一个名字：每一项都必须说明实际 class、语义基座、可访问状态和行为责任。构件 CSS 或类别页失配时，构建直接失败。

行为脚本与边界

目前的渐进增强脚本是 animations-complete、overlay、tabs、disclosure、toc、reveal 与 copy。它们不构成运行时框架，更不承载业务状态。复杂级联选择、富文本编辑、通用图标生态和 Figma kit 是尚未建设的真实缺口，不应由“多造几个组件”掩盖。
