框架总览 · Framework Overview

文心 · 万形

不是一套“长得像什么”的 UI 库，而是一套把设计判断、媒介适配、可复用构件与交付验证连成闭环的内容型前端框架。

一个魂，万种形

文心决定什么不能变；万形决定同一个判断如何在不同媒介、页面任务和交互密度中落地。构件与验证不是附录，它们是让这套设计能够被团队复用、检查和演化的机制。

01

文心 · Soul

七维度模型中的不变之魂：A9 克制、B9 温暖极简、D9 暖土调；再由排版、节奏、动效和文化语境具体化。

权威源：spec/soul/ 与 core.css

02

万形 · Forms

F1–F9 媒介约束与 A–E 页面原型。媒介决定物理条件，页面任务决定阅读轨或应用轨。

权威源：spec/media.md 与 kit/patterns/

03

构件 · Kit

三层 token、基础层、组件、模式和行为脚本。每层只解决它该解决的问题，不把业务产品抽象塞进通用库。

权威源：kit/

04

验证 · Assurance

颜色、禁令、token、站点结构、render contract、a11y 与人工设备检查共同定义“可交付”。

权威源：scripts/ 与 tests/

一件新产出如何进入系统

  1. 先定形选择 F1–F9 媒介和 A–E 页面任务；这一步决定布局、动效强度和轨道，不是选一个视觉皮肤。
  2. 再守魂从核心 token、排版节奏、色彩和禁令出发；任何偏离先对照 A9 / B9 / D9 与双轨仲裁。
  3. 后组构件用 pattern 组织页面，再以组件完成输入、导航、内容展示与反馈；HTML/ARIA 契约是接口的一部分。
  4. 最后验收运行构建与检查；自动检查证明静态底线，设备级可访问性和真实内容仍保留人工门槛。

按问题进入

你要解决的问题先看什么再用什么
定义一份内容产品的视觉与语言边界文心、双轨仲裁token、字体、间距与动效规则。
把同一设计落到网页、移动、印刷或报告万形 / F1–F9对应 form token 与媒介强制的决定。
组织一张内容页、列表、着陆页或工具页页面原型 A–E构件，而不是从零散组件名猜用途。
把产物交给另一位设计师或工程师验证DTCG token、render contract 与可复现命令。

最小接入

<link rel="stylesheet" href="kit/index.css">
<main class="wx-container wx-container--article">
  <h1>内容先于界面</h1>
</main>

需要单文件时使用 kit/dist/wenxin.css；需要媒介适配时额外引入相应的 kit/tokens/forms/fN-*.css。不是所有项目都应使用这套系统：dashboard、电商、CRM、游戏与邮件通讯在设计范围外。

框架成熟度

成熟不等于组件数量或门户页面数量；它意味着每一层都有明确权威源、公开契约、可组合边界和验证责任。当前证据与缺口在 MATURITY.md。
