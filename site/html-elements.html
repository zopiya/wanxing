元素浏览器默认的问题这里怎么处理
i cite dfn var address中文没有真正的斜体，浏览器合成的伪斜体像渲染故障。:lang(zh) 下改为加重，与 em 一致。
mark默认 #ff0，页面上没有第二个这么饱和的颜色。暖调 --color-accent-subtle 底，正文墨字，9.75:1。
sub sup默认 vertical-align 会撑开所在行的行高。line-height: 0 + 相对偏移，行距不变。
abbr[title]各浏览器下划线不一致，且 title 只在悬停时出现——触屏读者永远看不到。点线下划线标出"这里有东西可查"，并在文中同时给出全称。
q自动引号取自 lang，中文需要直角引号且嵌套层不同。中文「」『』，西文 “” ‘’。
u与链接下划线无法区分。保留下划线，但不建议使用——需要强调用 em，需要标注用 mark。
ins del sins 的下划线同样像链接。ins 下划线取 --color-success；删除线用 from-font 粗细。
ruby rt rp注音字号与位置未定义。0.5em、置于上方、次级墨色；rp 隐藏。中文优先的系统不能不管注音。

裸控件到此为止

<fieldset> 的 2px 凹槽边框、<progress> 的平台蓝、勾选框的平台蓝， 这些是浏览器塞给你的违规默认值，base 层负责清掉。 但真正的表单排布、校验时机、错误汇总和提交状态属于组件契约—— 见数据录入与表单页。 base 保证裸控件不难看，不保证它是一个好表单。

所有嵌入元素——img picture svg video canvas iframe audio embed object——都受 max-width: 100% 约束。 少了这一条，一个 iframe 就能把整页推宽。

分节元素

article section nav aside header footer main hgroup search 不带任何视觉样式，这是有意的： 它们是文档结构，不是外观。给 section 加边框会让人用它来"画一个框"， 而这套语言从不用四边包围的容器分组。布局由 布局组件 负责。

一个例外

main 必须存在——check:a11y 检查每一个生成页面是否有 main 地标，没有则构建失败。
