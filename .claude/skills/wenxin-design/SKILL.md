# 文心 · 万形

内容型产品的设计语言。**文字即界面，留白即设计，克制即力量。**

## 先做这一步

读 `kit/wenxin.json`（约 29KB）。它由来源派生，含不变之魂、三层仲裁、两种排除、
禁令（可检查的与需判断的）、全部 token、71 条组件契约、判定索引。
**不要从散文里推导数值**——`kit/tokens/core.css` 是唯一真源。

产出之后**不要声称合规，跑一遍**：

```sh
npx wenxin audit <file>     # 吐 JSON；hardGates 非空即不合规
```

## 三条不可改

`A9 克制之美` / `B9 温暖极简` / `D9 暖土调`。

改动它们，产物就不再属于这套语言。你若认为必须改，写进 `spec/DECISIONS.md`
作为待议项，**不要单方面改**。

## 冲突判定：三层，自上而下

哲学约 60%，主流惯例约 40%。这个比例是下面三层产生的**结果**，不是口味。

| 层 | 规则 |
|---|---|
| **1 · 全局底线** | 无障碍与基本可用性，**惯例无条件优先**，两轨都适用：WCAG 2.2 AA、可见焦点态、键盘可达、触控目标、颜色不作唯一信息载体、`prefers-reduced-motion` |
| **2 · 按形态分轨** | 阅读轨全量应用视觉约束；应用轨放宽。**采用页面原型 E（工具 / 表单）的页面会翻转它所在形态的轨道** |
| **3 · 组件类别** | 数据录入与反馈类组件**永远按惯例处理**，无论所在轨道。表单就是表单 |

遇到冲突，从第 1 层往下查，**第一个命中的层就是答案**。不要临时争论。

## 最常撞上的四件事

**没有卡片。** 用 `wx-entry`——单边线 + 留白。禁令针对的是*几何形状*（四边包围：边框、
阴影或填充底色三者任一 + 圆角），不是那个名词。不要以 `.panel` `.box` `.tile`
`.surface` 重新引入。浮层（`wx-modal` / `wx-drawer` / `wx-toast`）是唯一例外，
理由写在 D-21。

**每页至多两处强调色。** 品牌印章 ■ 占掉一处。图表里只有一个序列可以是 accent——
caption 正在讲的那一个。

**状态走 ARIA，不走类名。** `aria-current`、`disabled`、`open`，**永远不用 `.is-active`**。
这条由"禁止仅用颜色区分状态"推导而来：把 CSS 状态绑到无障碍树上，
就在结构上不可能出现读屏器感知不到的状态。

**类名 `wx-` 前缀 + BEM-lite，只允许一层 `__`。** 完整 BEM 会产出
`wx-article__header__title--large`，那正是这套系统在别处禁止的"产品味"。

## 两种排除，别弄混

拒绝一个组件请求之前，先分清是哪一种（D-23）：

- **哲学性排除**——卡片、spinner、骨架屏、自动轮播、水印。它们是这套系统的**身份**，
  不因范围扩大而回来。
- **范围性排除**——滑块、上传、日期、树、气泡。曾因适用范围被排除，范围扩大后**已经实现**。

如果某个需求真的需要哲学性排除的东西，说明**需求本身值得讨论**，不是禁令值得放宽。

## 需要判断、不能机械检查的规则

`kit/contracts/forbidden.json` 的 `judgement` 数组里有四条：卡片几何、色块背景分区、
强调色预算、装饰插画。**没有任何检查在守它们**，每条都写明了为什么不可检查。

一条没被标出来的不可执行规则，会被误以为有人在守——这是这个仓库反复吃过的亏。
遇到这四条，靠判断，并在提交信息里写清理由。
