# 判定日志 · Decisions Log

> 记录哲学与惯例冲突时的逐条判定。规则见 [tracks.md](./tracks.md)。
> 每条注明：冲突是什么、判给哪边、依据哪一层、为什么。

格式：`D-n · 标题` → 判定 → 层级 → 理由。

---

## D-1 · 语义色缺失

**冲突**　旧 token 只有 `--color-accent`，没有 danger / success / warning。
但 [aesthetics.md](./soul/aesthetics.md) **C-6** 明写「每个语义色 token（accent, danger, success,
warning）只用于其语义目的」—— 准则假设它们存在。同时[第一层底线](./tracks.md)要求
「颜色不可作为唯一信息载体」，反过来意味着**必须先有颜色**才谈得上颜色加文字。

**判定**　补齐。新增 `--color-danger` / `--color-success` / `--color-warning` 及 `-subtle` 变体，
低饱和暖调，满足 AA 对比且彼此可区分。**不计入 accent 预算。**

**层级**　第一层（全局底线）

**理由**　这不是"惯例赢了哲学"。哲学从未主张"不要语义色"，只主张"不要装饰性的高饱和色"。
语义色是信息通道，不是装饰 —— 旧 token 的缺失是疏漏，不是立场。

## D-2 · danger 与 accent-hover 撞色

**冲突**　取材发现旧 admonition 里 `danger` 用的是 `#A84030`，
**与 `--color-accent-hover` 完全同值**。这直接违反 C-6「primary accent 不应复用为 error 色」。

**判定**　**已解决：`--color-danger: #5C1F2F`（牛血红 oxblood）。**

在暖土色域内做了一次约束求解：要求 AA 达标、与正文色 ΔE ≥25（不能被误读为正文）、
且与 accent 色差最大。结果指向两个方向——高饱和亮红（`#CA1616` 一类，属被禁色）
与深牛血红。取后者。

最终四色两两色差最小值 **ΔE = 28**（accent ↔ danger），全部互不混淆：

| | 值 | 对暖白 | 说明 |
|---|---|---|---|
| accent | `#8B3525` | 7.00:1 | 不变 |
| danger | `#5C1F2F` | 10.90:1 | 新 |
| warning | `#7D5E12` | 5.30:1 | **旧值 `#8B6914` 实测 4.47:1，不达 AA，已修** |
| success | `#4F6B3A` | 5.27:1 | 从棕橄榄（36°）移到苔绿（94°）——旧值与 warning 只差 4° 色相，无法区分 |

**层级**　第一层（C-6 属阻断性范畴的语义完整性）

**理由**　如果 danger 和 accent 长得一样，用户无法区分"这是重点"和"这有危险"。
这是信息设计的失败，不是审美问题。

## D-3 · 主提交按钮可以填充

**冲突**　[forbidden.md](./soul/forbidden.md) 禁止填充按钮；但表单需要一个视觉上找得到的主操作，
这是普遍的可用性惯例。

**判定**　`wx-btn--primary` 升格为一等变体。默认仍是 ghost 线框，
**填充仅用于真正的主操作，每视图至多一个**。约束从"禁止"改为"限量"。

**层级**　第三层（数据录入组件按惯例处理）

**理由**　旧规范其实已经写了「除表单绝对必要的主提交按钮」—— 系统本就预见了这个妥协，
只是把它写成括号里的例外。升格为命名变体后，它变得可数、可审计，比藏在括号里更克制。

## D-4 · 卡片：保留禁令，但改写措辞

**冲突**　规范说"没有 card 组件"，但取材统计显示 `card` 类出现在 **9 个形态示例中的 4 个**。
需求是真实且跨形态的。

**判定**　保留禁令，但做三件事：
1. 措辞从含糊的「卡片 + 阴影」改为定义**几何形状**：「四边包围的方框（边框/阴影/填充底色三者任一 + 圆角）」。
2. 提供正名的替代品 `wx-entry`，并在 [components.md](./soul/components.md) 正面回答"不用卡片怎么分组"。
3. 应用轨给 `wx-list--grouped` 一个有边界的例外（走边框，仍禁阴影）。

**层级**　第二层（形态分轨）

**理由**　旧措辞可被合理理解为"只禁止两者的组合"，所以违规是措辞的锅。
更重要的是：**需求真实存在，只提供禁令而不提供替代品，同样的东西会以别的名字再长出来**。
取材还发现，示例里 `box-shadow` 出现 **0 次** —— 实际从未有人违反真正的禁令（阴影），
违反的只是命名。

## D-5 · F7 海报的 accent 规则与 Web 不同

**冲突**　全页 accent ≤2 处是灵魂层约束。但 F7 原文写明「标题使用 accent 是允许的 ——
这是海报的点睛」，并给了理由：单页画布的"全页"语义与可滚动页面不同。

**判定**　承认为**形态层对灵魂层的合法适配**，但必须显式声明：
F7 的预算是「标题 1 处 + 署名 1 处」，仍然 ≤2，只是分配方式不同。
审计器按形态分派预算，而非走 `allowedDeviations`。

**层级**　第二层（形态分轨）

**理由**　这不是放宽，是同一条约束在不同画布语义下的正确解释。
一张海报的"全页"就是一张画布，而一个 Web 页面的"全页"可能有十屏高。
把它写成偏离反而会掩盖它其实合规。

## D-6 · 图表不引入分类色板

**冲突**　多序列图表天然需要多个可区分颜色，而系统禁高饱和色、限 accent ≤2 处。

**判定**　不引入分类色板。序列用**墨色阶梯 + 线型**编码；
accent 只标记论点项。≥5 序列的密集图表**声明为范围外**，改用小倍数。

**层级**　第二层之上 —— 这是灵魂层决策，两轨相同

**理由**　仪表盘已在[适用范围](./soul/philosophy.md#适用范围--scope)之外，
所以"多系列密集图表"本就不是这套语言该解决的问题。
承认边界比引入一族新颜色更诚实 —— 后者会实质性改变 D9 暖土调的色彩边界，
而 D9 属于[不变之魂](./soul/philosophy.md#不变之魂与可变之形--invariant-soul-flexible-form)。

**代价**　已在 [data-viz.md](./soul/data-viz.md) 明确写出，不粉饰。

## D-7 · 骨架屏不做

**冲突**　加载占位是常见惯例，但 skeleton 的标准实现是流动的 shimmer 循环动画，
属于[被禁止的循环动效](./soul/motion.md)。

**判定**　不做这个组件。需要占位时用 `wx-rule` 加留白。

**层级**　第二层（阅读轨视觉约束）

**理由**　去掉 shimmer 之后，骨架屏就是几根静态的发丝线 —— 那已经是 `wx-rule`，
不需要一个新组件名。这里不存在真正的冲突，只是标准实现恰好用了被禁的手段。

## D-8 · 弃置 opendesign 适配层

**冲突**　仓库里有一个 `opendesign/` 目录，把文心打包成第三方 `DESIGN.md` 格式，
并要求 tokens 在三处手工同步。

**判定**　整个弃置。本项目是文心与万形本身；Open Design 适配是**日后从这里派生出去的另一个项目**。

**层级**　不适用（项目边界决策，非设计冲突）

**理由**　适配层反向绑定原项目，是包袱不是资产。
顺带消掉的"三处手工同步"问题本就是适配层带来的，而非设计系统固有的。

## D-9 · 暗色 accent 不达 AA

**冲突**　落地暗色调色板时实测：旧文档与旧示例记载的暗色 accent `#C4533E`
在夜底 `#1A1816` 上只有 **3.92:1**。accent 用于链接与强调，是正文级用途，需要 4.5:1。

**判定**　保持色相（9°）与饱和度（58%）不变，仅抬升明度至 `#CF5F4A`（4.54:1）。
hover 态同步调整为 `#DE7059`。

**层级**　第一层（A-1 对比度，阻断性）

**理由**　这不是设计取舍，是一处从未被测量过的缺陷。
保持色相与饱和度而只动明度，是为了让同一个颜色在两种模式下**仍然是同一个颜色**
（准则 M-9），而不是变成另一种红。

**顺带说明**　这类问题此前无法被发现，因为暗色值只存在于文档散文里，
从未进入过任何可以被检查的文件。现在 `dark.css` 是真实代码，
`npm run check` 可以对它做断言。

## D-10 · functional ink 从生产站反哺 token

**冲突**　core 把 `#888580` / `#B0ABA4` / `#C8C3BA` 命名为文字色，规范又要求辅助文字
≥4.5:1。田野实测它们在真实站点只有 3.23 / 2.00 / 1.68:1。与此同时，`zopiya.com`
与博客独立引入了 `#706D68` 作为功能文字，实测 4.52:1。

**判定**　**A · 实践比规范好。** 吸收 functional ink；重排亮/暗 `text-*` 阶梯，所有命名为
文字的 token 都必须能在对应暖地面排正文小字。focus 从半透明改为不透明 accent。

**层级**　第一层（对比度与焦点态）

**理由**　这不是把视觉做重，而是停止拿边框灰排文字。两个生产站各自走到同一值，是比纸面命名
更强的证据。`check:colors` 现在把 34 个亮/暗文字、语义面、accent、focus 组合与 12 组语义色差变成硬检查。

## D-11 · `wx-entry` 增加连续流，不增加卡片

**冲突**　`wx-entry` 能分隔短列表，但片语与博客的长时间流需要“这些条目属于同一条时间轴”的
连续性。只有单边 rule 时，使用者会继续手写 rail/dot，kit 的替代品仍不完整。

**判定**　**A · 实践比规范好。** 新增 `wx-timeline`，由 rail / dot / content 三槽组成；
无四边框、无阴影、无填充容器，起止处不用渐变。

**层级**　第二层（F1/F6 列表形态），不触碰卡片禁令

**理由**　生产站没有让卡片回来，反而给出了更好的非卡片答案。吸收结构，拒绝片语用渐变淡出
线端的实现细节，因为渐变触及 A9。

## D-12 · 真实内容站上的 accent 预算分两种判法

**冲突**　品牌首页与博客能把静态 accent 控制在 2 个；片语热力图有多级 accent alpha，
花园又把 accent 映射成代码 keyword，一篇文章产生约 232 个 accent 文本节点。

**判定**　片语页面若声明原型 E / application，多个**交互状态**属于 **B · 合法形态适配**；
但热力图仍不得只靠颜色传量。花园的 syntax accent 属 **C · 漂移**，改用独立暖墨语法色。
不改全局 ≤2，也不把“同一 CSS token”偷换成“一种语义角色”来绕预算。

**层级**　第二层决定片语预算；第一层决定热力图信息编码；A9/D9 决定花园漂移

**理由**　application 可以放宽强调次数，不能放宽颜色单独表意；editorial 代码重复数百次更不能
把强调色降格成普通分类色。矛盾应拆开，不抹成一条例外。

## D-13 · 暗色触发方式可多样，暗色 accent 不可漂

**冲突**　首页/博客跟随系统，片语用 `data-theme` 手动切换，花园用 `saved-theme` 覆盖；
三站仍用旧 `#C4533E` 或自定 `#B84A36`，后者对夜底只有 3.43:1。

**判定**　触发方式是 **B · 合法形态适配**；旧/自定 accent 是 **C · 漂移**，回归
`#CF5F4A`。kit 继续同时提供 system media 与 `data-theme` 两条路，不新增第四套颜色。

**层级**　第二层（交互方式）+ 第一层/D9（颜色值）

**理由**　“怎么进入暗色”由产品决定；“进入后还是不是同一个暖土色系统”不由产品随意决定。

## D-14 · F1 的 40em 长文与作者侧栏

**冲突**　F1 原文把 640px 单列写得过硬，并用“侧栏是 F6 的手段”做边界；生产博客用
18px/720px（正好 40em）和固定作者栏，却没有 F6 的搜索、版本与知识树。

**判定**　**B · 合法形态适配。** 原型 A 长篇叙事可到 40em；没有全文搜索/版本/知识树的
作者侧栏仍可属于 F1。默认 token 不改。

**层级**　第二层（F1 / 原型 A）

**理由**　决定 F1/F6 的是页面任务，不是“有没有一根侧栏”。40em 仍在既定 CJK 30–40 字边界。

## D-15 · F6 允许三轨，不允许缺地标

**冲突**　花园的左知识树 + 中正文 + 右 TOC/关系入口比两栏规范更适合大型知识库；
但实际 DOM 缺 `<main>/<nav>/<aside>` 地标。

**判定**　三轨布局是 **B · 合法形态适配**；缺地标是 **C · 漂移**。规范吸收布局，
并把三轨对应语义与 skip link 写成验收项。

**层级**　第二层决定布局；第一层决定语义可达性

**理由**　水可以取三栏之形，读屏器不能因此失去主内容入口。

## D-16 · 字体策略按成本适配，F6 CDN 不适配

**冲突**　品牌首页与片语只用系统 fallback，博客自托管子集，花园依赖 Google Fonts 与 jsDelivr。

**判定**　轻首页/工具的系统 fallback 是 **B · 合法形态适配**；博客自托管是正例；
F6 长期文档站字体 CDN 是 **C · 漂移**，回归自托管 + `unicode-range`。

**层级**　第二层（C/G 排版交付）+ 全局 M-6/M-8

**理由**　规范要求的是可持续、可复现的字体交付，不是每页必须下载同一文件。
系统 fallback 可以比下载更好；第三方 CDN 则把可用性与隐私成本交给站外。

## D-17 · 上线不豁免目标尺寸、状态树与对比度

**冲突**　博客有 20px 社交链接和 `.active`；片语有 16–19px 按钮与 `--active/--open` 状态类；
花园有约 19px 侧栏链接；三站大量小字灰低于 AA。

**判定**　全部归 **C · 漂移**。站点不在本次修改范围，只给回归建议：扩命中盒、
改 `aria-current/selected/pressed/expanded`，用 functional ink。

**层级**　第一层（无障碍与基本可用性）

**理由**　田野证据可以推翻纸面审美，不可以推翻无障碍底线。线上存在只能证明检查缺失，
不能把失败升级成惯例。

## D-18 · 品牌呼吸按页面任务，不按组件存在

**冲突**　首页、博客、花园都让 ■ 以 4s 循环呼吸。首页的唯一任务是建立身份；
博客文章和文档的任务是阅读/检索。

**判定**　F1 品牌着陆页可声明 `E9-2`，属于 **B · 合法形态适配**；博客文章与 F6 文档中的
循环是 **C · 漂移**。`wx-seal--breathing` 仍只在 `data-motion="E9-2"` 下生效。

**层级**　第二层（E 可变）

**理由**　同一个动画在不同页面任务里不是同一个决定。组件出现不自动授权更高动效强度。

## D-19 · F7 社交卡片旧协议不并入现行规范

**冲突**　`f7-social-card.md` 是重构时一并留下、但从未被规范入口引用的长篇历史草案；它允许
蓝/绿替代 accent，使用 `#888580` / `#B0ABA4` 等低对比文字色，并含渐变和“悬浮卡片”构图。
这些内容同时违反 D9 暖土调、WCAG AA 与 M-2/M-10，不能因为文件位于 `spec/` 就倒推为规则。

**判定**　**C · 内部遗留漂移**。保留原文并在文件首部明确标为 non-normative，防止历史证据被
悄悄改写；任何新 F7 产物只遵循 `f7-poster.md`。若日后重做社交长图，应从现行 token 和 F7
契约重新派生，不从旧 Tailwind 片段修修补补。

**层级**　第一层（AA/M 准则）+ 不变之魂（D9）

**理由**　这里没有可仲裁的媒介例外：固定画布能改变字号、密度和安全区，不能授权另一套文化
色盘或不可读文字。把它标成历史草案，比批量替色后假装已经验证 15 套版式更诚实。

## D-20 · 文字灰阶从六档收到四档

**冲突**　把全部 `text-*` 抬到 AA 之后，`secondary` / `muted` / `tertiary` / `functional`
四个 token 的实测明度差只剩 ΔL\* 1.2 与 2.0 —— 低于可辨阈。四个名字渲染成两个层级，
而 `tertiary` 在 `kit/` 与 `examples/` 里的引用次数是 **0**：它只存在于文档中。

**判定**　**收到四档**：`heading` / `primary` / `secondary` / `functional`，相邻 ΔL\* ≥ 11。
`tertiary` 直接删除（无人使用）；`muted` 的 24 处引用全部并入 `functional` ——
逐条查过，它们本来就是占位符、面包屑分隔、页码标签、禁用按钮这类 UI 元数据，
`functional` 正是这个语义。

**层级**　第一层（AA）+ 减法优先

**理由**　AA 底线把可用明度范围压到 L\* 23.7–46.2，这段距离容不下四个可辨层级。
与其保留四个名字假装有四档，不如承认只有四档（含 heading）并让每一档都真的看得出来。
**能表达的层级数是被对比度底线决定的，不是被命名决定的** —— 这是一次真正的减法，
不是妥协。

## D-21 · 浮层可以有"面"，但只借这一样

**冲突**　`wx-modal` / `wx-drawer` / `wx-toast` 天然需要与底层页面分离，
而系统禁止四边包围容器。

**判定**　**允许浮层拥有面**：发丝线边缘 + `--color-scrim` 暖色遮罩 + 至多 `--radius-md`。
**不借**阴影、渐变、更大圆角。三者一律走原生 `<dialog>` / `aria-live`。

**层级**　第一层（基本可用性）+ 第三层（反馈类按惯例）

**理由**　一个不像独立层的浮层不是克制，是可用性缺陷 —— 读者无法判断什么可以关闭、
什么是页面本身。两条仲裁层指向同一个方向。但"需要分离"只授权**分离**这一件事，
不授权把整套产品视觉搬进来：分离用发丝线就够了，阴影是另一回事。

---

## D-22 · 禁令要能被检查到，否则等于不存在

**冲突**　`check:forbidden` 的粗边框正则只匹配 `border-top/right/bottom/left`，
不认逻辑属性。`kit/` 全面使用逻辑属性，于是 `border-inline-start: 2px` 一直畅通无阻——
`note.css`、`sidebar.css`、`markdown/admonitions.css` 三处 2px 边框存在了整个重构期间，
而检查器一直是绿的。

**判定**　正则扩展到 `inline` / `block` 及其 `start` / `end` 变体；三处 2px 全部改用
`var(--stroke-mark)`（1.5px，系统签名描边，本就是禁令的法定例外）。

**层级**　工程纪律

**理由**　与 [D-9](#d-9--暗色-accent-不达-aa) 和田野审计发现的灰阶问题是同一个教训的第三次出现：
**只在散文里存在的规则不会被遵守，只有能被执行的检查才是规则。**
禁令的措辞和检查器的实现之间任何一道缝隙，最终都会被代码填满。

## D-23 · 两种排除不是一回事

**冲突**　组件清单原先把"滑块 / 上传 / 日期选择器 / 树 / 气泡卡片"和"卡片 / 骨架屏 / 加载动画"
写在同一节"明确不做"里。范围扩展到完整组件库后，需要判断哪些该实现。

**判定**　拆成两类，处理方式不同：

- **哲学性排除**——卡片、加载动画、骨架屏、自动轮播、水印。它们与 A9（减法）或动效禁令直接冲突，
  **不随范围扩大而放开**，因为它们就是这套系统的身份。
- **工程性排除**——滑块、上传、日期、树、气泡。当初的理由是"适用范围不含工具类场景"，
  是范围判断而非价值判断。范围变了，它们就该实现，且实现时不需要任何哲学让步。

**层级**　不变之魂（A9）划出第一类；第二类无仲裁冲突

**理由**　把两种排除混在一起，会让人以为整份清单都可以谈判，或者整份都不可以。
真正的区别是：<strong>拒绝的理由是"这违反我们相信的东西"，还是"我们暂时用不上"。</strong>
前者是身份，后者是待办。

## D-24 · 拖放区可以是四边框

**冲突**　文件上传的拖放区天然是一个四边包围的矩形，与卡片禁令冲突。

**判定**　**允许**，虚线发丝边框，无填充、无阴影、无超过 `--radius-md` 的圆角。

**层级**　第一层（基本可用性）+ 第三层（数据录入按惯例）

**理由**　与 [D-21](#d-21--浮层可以有面但只借这一样) 同源：<strong>边界不是装饰，它就是信息</strong>——
它标示可拖放区域到哪里为止。一个看不见边缘的拖放目标是可用性缺陷。
同样地，"需要边界"只授权边界本身，不授权把整套产品视觉搬进来。

## D-25 · 九形态不再是文档的组织方式

**冲突**　F1–F9 曾经既是规范的组织结构，也是示例目录的结构。但读者第一次接触这套系统时，
想知道的是"色彩怎么用、表单怎么做"，而不是"第六形态的侧栏规则"。
按媒介分章把常用信息打散到九个文件里。

**判定**　文档站按**价值观 / 全局样式 / 设计模式 / 组件**组织；九形态的差异压缩进
`site/media.html` 一页的对照表。`spec/forms/` 与 `examples/` **保留**——
后者是 `audit:examples` 的验收对象，删掉等于删掉覆盖。

**层级**　无仲裁冲突（表达方式，非设计判断）

**理由**　媒介差异是真实的，但它是**查表信息**而不是入门路径。
把它从主干移到附录，主干才能按读者的问题组织。
保留示例则是另一条原则：<strong>验收测试不因为文档换了结构就该删除。</strong>

## D-26 · 删除九份夹具，连同它们喂养的检查

**冲突**　`examples/f1..f9/` 名义上是演示页，实际是 21 项 `profileSpecificChecks` 的唯一 subject。
文档站建成后它们的演示价值消失了，但直接删掉会让审计机器失去检查对象。

**判定**　**全部删除**，检查一并删除。`audit-all.mjs` 与 `audit-selftest.mjs` 删除；
`render-audit.mjs` 移除声明式检查分派与按 profile 的分支（908 → 703 行），
保留为**独立工具**（`npm run audit <file>`），从 `npm run check` 中移出。

**层级**　工程判断，非设计仲裁

**理由**　三个选择里只有两个是诚实的：**保留夹具并保留检查**，或者**两个都删**。
中间路线——合成一个页面、只留一个 profile——会让 18 项检查失去 subject，
变成看起来活着的死代码，正是这个仓库反复踩的坑。既然演示价值已由站点取代，
就不该为了留住检查而保留九个没人看的页面。

**代价（明确记录）**　`pt-scale`、`touch-targets`、`no-motion`、`figure-numbering`
等媒介规则**回到了"只写在文档里"的状态**。这与 [D-22](#d-22--禁令要能被检查到否则等于不存在)
的结论方向相反，是一次有意识的取舍，不是遗忘：这些规则的适用者是使用这套系统的人，
而不是这个仓库本身，仓库里没有它们的宿主页面。

## D-27 · 删除分媒介整包

**冲突**　`kit/dist/wenxin-f1..f9.css` 九个文件合计 30,358 行。

**判定**　**删除**。只保留 `wenxin.css`，媒介 token 单独引入。

**层级**　工程判断

**理由**　每个包都是"完整 kit + 十几个 token"，九个包相对基础包的**真实差异合计 145 行**，

维护九份近似副本。**生成物的体量应该与它承载的信息成比例。**

## D-28 · 对比度要按"面"测，不是按"页面底色"测

**冲突**　`check:colors` 只把每个前景色对 `--color-bg-warm` 测一遍，绿了十一个月。
实际排查发现代码块这一处三重失败：`--code-comment` 2.87:1、`--code-punctuation` 3.52:1、
以及 `.wx-code__head` 继承的 `--color-text-functional` 在 `bg-subtle` 上 4.41:1 ——
两个主题都不合格。**检查没有洞，是检查的坐标系少了一维**：它知道有哪些前景色，
不知道有哪些面。

**判定**　三件事：

1. **代码面从 `bg-subtle` 改为 `bg-base`**（`--code-bg`，四处调用统一走它），
   把元数据行的余量买回来。
2. **`--code-comment` / `--code-punctuation` 抬到 4.5:1 之上**。注释是代码块里
   最常被当散文读的部分，是最不该先淡出去的东西；"退让"有底线。
3. **`check:colors` 扩到按面测**：正文三档对全部七个面，语法色板对代码面。
   30 对 → 94 对。

**`--color-text-functional` 只在 `bg-warm` 与 `bg-base` 上持牌。**
让它在 `bg-subtle` 上过 4.5:1 需要压到 L\* 44.9，距 `secondary` 只剩 ΔL\* 9.8 ——
低于 **D-20** 定的 11。档距和暗面二者不可兼得，于是限制的是**面**，不是档。
逐条查过：`wx-segmented__option[aria-selected]` 与 `wx-calendar__day[disabled]:hover`
本来就各自覆写了颜色，代码库对这件事一直是小心的，真实失败只有代码块一处。

**层级**　第一层（AA 底线，双轨无条件）

**理由**　与 **D-22** 同一条教训的另一面。D-22 说禁令要能被检查到；这一条说
**检查覆盖的维度本身也会有盲区，而盲区的绿色比没有检查更危险**——它会被当成证据引用。
三条负控都验过：恢复旧 comment 值、把代码底退回 `bg-subtle`、调淡 `text-secondary`，
分别在预期位置失败。
