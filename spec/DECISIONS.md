# 判定日志 · Decisions Log

> 记录哲学与惯例冲突时的逐条判定。规则见 [tracks.md](./tracks.md)。
> 每条注明：冲突是什么、判给哪边、依据哪一层、为什么。

格式：`D-n · 标题` → 判定 → 层级 → 理由。

---

## D-1 · 语义色缺失

**冲突**　旧 token 只有 `--color-accent`，没有 danger / success / warning。
但 [aesthetics.md](./soul/aesthetics.md) **C-6** 明写「每个语义色 token（accent, danger, success,
warning）只用于其语义目的」—— 准则假设它们存在。同时[第一层底线](./tracks.md)要求
「颜色不可作为唯一信息载体」，反过来意味着**必须先有颜色**才谈得上颜色加文字。

**判定**　补齐。新增 `--color-danger` / `--color-success` / `--color-warning` 及 `-subtle` 变体，
低饱和暖调，满足 AA 对比且彼此可区分。**不计入 accent 预算。**

**层级**　第一层（全局底线）

**理由**　这不是"惯例赢了哲学"。哲学从未主张"不要语义色"，只主张"不要装饰性的高饱和色"。
语义色是信息通道，不是装饰 —— 旧 token 的缺失是疏漏，不是立场。

## D-2 · danger 与 accent-hover 撞色

**冲突**　取材发现旧 admonition 里 `danger` 用的是 `#A84030`，
**与 `--color-accent-hover` 完全同值**。这直接违反 C-6「primary accent 不应复用为 error 色」。

**判定**　**已解决：`--color-danger: #5C1F2F`（牛血红 oxblood）。**

在暖土色域内做了一次约束求解：要求 AA 达标、与正文色 ΔE ≥25（不能被误读为正文）、
且与 accent 色差最大。结果指向两个方向——高饱和亮红（`#CA1616` 一类，属被禁色）
与深牛血红。取后者。

最终四色两两色差最小值 **ΔE = 28**（accent ↔ danger），全部互不混淆：

| | 值 | 对暖白 | 说明 |
|---|---|---|---|
| accent | `#8B3525` | 7.00:1 | 不变 |
| danger | `#5C1F2F` | 10.90:1 | 新 |
| warning | `#7D5E12` | 5.30:1 | **旧值 `#8B6914` 实测 4.47:1，不达 AA，已修** |
| success | `#4F6B3A` | 5.27:1 | 从棕橄榄（36°）移到苔绿（94°）——旧值与 warning 只差 4° 色相，无法区分 |

**层级**　第一层（C-6 属阻断性范畴的语义完整性）

**理由**　如果 danger 和 accent 长得一样，用户无法区分"这是重点"和"这有危险"。
这是信息设计的失败，不是审美问题。

## D-3 · 主提交按钮可以填充

**冲突**　[forbidden.md](./soul/forbidden.md) 禁止填充按钮；但表单需要一个视觉上找得到的主操作，
这是普遍的可用性惯例。

**判定**　`wx-btn--primary` 升格为一等变体。默认仍是 ghost 线框，
**填充仅用于真正的主操作，每视图至多一个**。约束从"禁止"改为"限量"。

**层级**　第三层（数据录入组件按惯例处理）

**理由**　旧规范其实已经写了「除表单绝对必要的主提交按钮」—— 系统本就预见了这个妥协，
只是把它写成括号里的例外。升格为命名变体后，它变得可数、可审计，比藏在括号里更克制。

## D-4 · 卡片：保留禁令，但改写措辞

**冲突**　规范说"没有 card 组件"，但取材统计显示 `card` 类出现在 **9 个形态示例中的 4 个**。
需求是真实且跨形态的。

**判定**　保留禁令，但做三件事：
1. 措辞从含糊的「卡片 + 阴影」改为定义**几何形状**：「四边包围的方框（边框/阴影/填充底色三者任一 + 圆角）」。
2. 提供正名的替代品 `wx-entry`，并在 [components.md](./soul/components.md) 正面回答"不用卡片怎么分组"。
3. 应用轨给 `wx-list--grouped` 一个有边界的例外（走边框，仍禁阴影）。

**层级**　第二层（形态分轨）

**理由**　旧措辞可被合理理解为"只禁止两者的组合"，所以违规是措辞的锅。
更重要的是：**需求真实存在，只提供禁令而不提供替代品，同样的东西会以别的名字再长出来**。
取材还发现，示例里 `box-shadow` 出现 **0 次** —— 实际从未有人违反真正的禁令（阴影），
违反的只是命名。

## D-5 · F7 海报的 accent 规则与 Web 不同

**冲突**　全页 accent ≤2 处是灵魂层约束。但 F7 原文写明「标题使用 accent 是允许的 ——
这是海报的点睛」，并给了理由：单页画布的"全页"语义与可滚动页面不同。

**判定**　承认为**形态层对灵魂层的合法适配**，但必须显式声明：
F7 的预算是「标题 1 处 + 署名 1 处」，仍然 ≤2，只是分配方式不同。
审计器按形态分派预算，而非走 `allowedDeviations`。

**层级**　第二层（形态分轨）

**理由**　这不是放宽，是同一条约束在不同画布语义下的正确解释。
一张海报的"全页"就是一张画布，而一个 Web 页面的"全页"可能有十屏高。
把它写成偏离反而会掩盖它其实合规。

## D-6 · 图表不引入分类色板

**冲突**　多序列图表天然需要多个可区分颜色，而系统禁高饱和色、限 accent ≤2 处。

**判定**　不引入分类色板。序列用**墨色阶梯 + 线型**编码；
accent 只标记论点项。≥5 序列的密集图表**声明为范围外**，改用小倍数。

**层级**　第二层之上 —— 这是灵魂层决策，两轨相同

**理由**　仪表盘已在[适用范围](./soul/philosophy.md#适用范围--scope)之外，
所以"多系列密集图表"本就不是这套语言该解决的问题。
承认边界比引入一族新颜色更诚实 —— 后者会实质性改变 D9 暖土调的色彩边界，
而 D9 属于[不变之魂](./soul/philosophy.md#不变之魂与可变之形--invariant-soul-flexible-form)。

**代价**　已在 [data-viz.md](./soul/data-viz.md) 明确写出，不粉饰。

## D-7 · 骨架屏不做

**冲突**　加载占位是常见惯例，但 skeleton 的标准实现是流动的 shimmer 循环动画，
属于[被禁止的循环动效](./soul/motion.md)。

**判定**　不做这个组件。需要占位时用 `wx-rule` 加留白。

**层级**　第二层（阅读轨视觉约束）

**理由**　去掉 shimmer 之后，骨架屏就是几根静态的发丝线 —— 那已经是 `wx-rule`，
不需要一个新组件名。这里不存在真正的冲突，只是标准实现恰好用了被禁的手段。

## D-8 · 弃置 opendesign 适配层

**冲突**　仓库里有一个 `opendesign/` 目录，把文心打包成第三方 `DESIGN.md` 格式，
并要求 tokens 在三处手工同步。

**判定**　整个弃置。本项目是文心与万形本身；Open Design 适配是**日后从这里派生出去的另一个项目**。

**层级**　不适用（项目边界决策，非设计冲突）

**理由**　适配层反向绑定原项目，是包袱不是资产。
顺带消掉的"三处手工同步"问题本就是适配层带来的，而非设计系统固有的。

## D-9 · 暗色 accent 不达 AA

**冲突**　落地暗色调色板时实测：旧文档与旧示例记载的暗色 accent `#C4533E`
在夜底 `#1A1816` 上只有 **3.92:1**。accent 用于链接与强调，是正文级用途，需要 4.5:1。

**判定**　保持色相（9°）与饱和度（58%）不变，仅抬升明度至 `#CF5F4A`（4.54:1）。
hover 态同步调整为 `#DE7059`。

**层级**　第一层（A-1 对比度，阻断性）

**理由**　这不是设计取舍，是一处从未被测量过的缺陷。
保持色相与饱和度而只动明度，是为了让同一个颜色在两种模式下**仍然是同一个颜色**
（准则 M-9），而不是变成另一种红。

**顺带说明**　这类问题此前无法被发现，因为暗色值只存在于文档散文里，
从未进入过任何可以被检查的文件。现在 `dark.css` 是真实代码，
`npm run check` 可以对它做断言。
