摘要 · Executive Summary

重构前的仓库只有规范正文，没有任何可复用产物；九个示例各自内联约 6,100 行重复 CSS。重构后建立了 token 单一真源、34 个组件、Markdown 渲染层与可执行的合规检查，并在过程中发现并修复了两处长期存在的对比度缺陷。

发现 · Findings

一 · 暗色模式从未落地

规范声明 color-scheme: light dark 却未定义任何暗色值。完整调色板只存在于散文与一个即将删除的示例文件中1。

二 · 两处对比度不达标

暗色 accent 实测 3.92:1、warning 实测 4.47:1，均低于 AA 要求的 4.5:1。这类问题此前无法被发现，因为相关数值从未进入过任何可被检查的文件。

建议 · Recommendations

  1. 把合规检查接入 CI —— npm run check 已可执行，成本极低。
  2. 任何新增 token 必须同时给出暗色值与对比度实测，不接受「稍后补」。
  3. 规范文件中的数值一律标注为摘录，真源只有一处。

1. 历史材料见 git 93fba710，删除前已完成取材。
